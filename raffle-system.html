Overview

The Raffle System is a Currency System add-on for running prize raffles. Members buy event tickets with your currency, rank the prizes they most want, and an admin rolls the winners — any number of times. A raffle appears right inside a forum post via a short token like [raffle=grandopening], as an interactive widget with a live countdown, buy and preference buttons, and the winners after the draw.

Prizes are a mix: Currency System items or currency amounts deliver automatically through the standard grant pop-up, while intangibles (a custom pet, a slot) notify the winner with a pop-up for you to fulfil by hand. It supports scheduled opens, purchase windows, per-member caps, gifting, free one-entry draws, and a paste-ready winner announcement.

Load order: it must sit below the Currency System (and Extras) on your Plugins page — it uses CS for currency, prize delivery, and its themed pop-ups.

Instruction Manual

The Setup Instructions inside the plugin’s own settings are a quick-start checklist. This is the full, plain-English walkthrough of every feature.

The Raffle System is an ADD-ON to the Currency System (CS). It lets you run prize raffles where members buy tickets with your forum currency, choose which prizes they most want, and an admin rolls the winners. A raffle appears right inside a forum post via a short token like [raffle=grandopening], as an interactive widget with a live countdown, buy buttons, and (after the draw) the winners.

It needs the Currency System installed and loaded ABOVE it (it uses CS for currency, prize delivery, and its themed pop-ups). This manual explains setup and every feature in plain English.

SETTING IT UP

  1. Load order: on your Plugins page the Raffle System must sit BELOW the Currency System (and CS Extras).
  2. Keys: the import creates four keys — raffle_events, raffle_tickets, raffle_display, raffle_admin. Confirm they exist on the Keys tab (raffle_display is the one that makes raffles visible to members — make sure it's there after upgrading).

2b. ★ AFTER EVERY IMPORT OR UPDATE: open the plugin's Settings and click SAVE once, even if you change nothing. ProBoards only COMMITS a plugin's key permissions when it is saved — a fresh import leaves them staged (they LOOK correct on the Key Permissions tab, but aren't in force yet), and until you Save, members can't read raffle_display and the raffle is invisible to them. Reloading won't fix it; only a Save will. (Do the same for the Currency System when you update it.) This is the single most common cause of "members can't see the raffle after an update."

  1. Key Permissions (important): the plugin's Key Permissions tab lists all four keys, each titled with the exact setting it needs. Set raffle_display to Members & Staff (Read + Write) — THIS is what lets members see raffles: it's a post key, so it loads with the post for everyone viewing it (a plain shared key, by contrast, is only delivered to people who've written to it, which is why members saw raw [raffle=id] text before). Set raffle_tickets to Members & Staff (Read + Write) so members can buy. Set raffle_events to Read Members & Staff but WRITE Staff only — the AUTHORITATIVE raffle list and roll results, so staff-only Write keeps members from altering raffles or forging wins. Set raffle_admin to Members & Staff (Read + Write). The import pre-sets these — just verify them.
  2. Admin page: create a Custom Page whose content is exactly the one line <div id="hcs-raffle-admin"></div> — this is your staff control panel. Keep it off the public menu.

The plugin's own Setup Instructions tab repeats this as a checklist.

Who can deliver prizes

Delivering an item or currency prize writes to the winner's account, so — exactly like the CS grant panel — it only works for staff who have the ProBoards "Edit Profiles" power. Make sure whoever rolls (or whichever group you use for auto-roll) has it. Intangible prizes (a custom pet, a slot) don't need it; the winner is notified by a pop-up and you fulfil those by hand.

CREATING A RAFFLE

Open your admin page and click "New raffle". Fill in:

  • Unique ID — letters, numbers, underscores, no spaces. This is the [raffle=ID] token you'll paste into a post. IDs can't be reused later, so pick a fresh one each time (e.g. grandopening, summer2026).
  • Title — the display name shown on the widget.
  • Preview image — an optional banner across the top of the widget. It has a Single image / Multiple images toggle. Single is one image URL. Multiple builds a composite of several OVERLAPPING pictures — a nice banner when, say, several pets are up for grabs: paste a URL and a fresh empty row appears beneath it automatically (no "add" button; keep pasting to add as many as you like), drag the handle on the left of each row to reorder them (the TOP row sits at the BOTTOM of the visual pile, each lower row drawn on top), and set the "Overlap" box to how far each image slides over the one before — a percentage like 40% (of the image size) or a pixel amount like 20px; blank = the images sit side by side. Each image keeps its aspect ratio (whole images aren't cropped), and the pictures wrap to a new line when they fill the width. A "Preview size (height, px)" box controls how large the banner shows — it applies to both single and multiple images. You can also give the preview images an OUTLINE that hugs the picture (it follows the image's shape, not a rectangular box): pick an outline color with the swatch and set an outline width — a width of 0 (or blank) means no outline. The whole Preview image control sits in its own bordered card in the editor so it reads as one group. The composite shows in the widget and in the Static copy (which needs Currency System Extras v1.0.90+).
  • Ticket price — how much currency one ticket costs. Set it to 0 for a FREE raffle (see below).
  • Min tickets per purchase — the smallest number a member can buy at once (usually 1).
  • Two separate caps, side by side — "Tickets a member can buy for themselves" and "Tickets a member can be gifted". They're independent: a self cap of 5 and a gift cap of 5 means a member may buy 5 of their own AND receive 5 gifted (10 held), not 5 combined. The self cap is blank = unlimited. The gift cap doubles as the gifting switch — blank or 0 turns gifting OFF for this raffle; any number 1 or higher turns it on and caps how many tickets a member can be gifted. (There's no separate "Allow gifting" checkbox — this one field says both whether and how much.)
  • Wins per member — 1 means "one prize each"; a higher number lets a member win several.
  • Total tickets the whole raffle can sell — optional cap on the COMBINED tickets everyone buys (not per member); when reached, the raffle auto-closes.
  • If prizes are left over — when fewer members can win than there are prizes, either leave the extras Unclaimed (reported to you), or Roll additional winners and set how many extra prizes one member may win (on top of Wins per member).
  • Timezone — one zone for the whole raffle (Eastern by default; daylight saving is handled for you). Times are stored as absolute moments, so they mean the same thing for everyone regardless of who created the raffle.
  • Opens at — keep "Open immediately" checked to start now, or uncheck it and pick Year / Month / Day and a time (Hour, Minute in 5-minute steps, AM/PM).
  • Ends at — an explicit end date and time (Year / Month / Day / Hour / Minute / AM/PM). This is when buying closes and the countdown runs to; you can change it later even while the raffle is open.
  • Grant message — the "Reason:" line a winner sees for an item/currency prize.
  • Who can't buy tickets — optionally bar member groups from this raffle. Tick "Staff (admins & moderators)" to keep staff out, and/or tick any of the named group boxes. Those group boxes come from the "Excludable member groups" setting on the Raffle System tab: pick the groups you might ever want to bar there (once), and they show up here as named tick-boxes on every raffle — no group IDs to hunt down, and you can change the list anytime. Being excluded means that member CANNOT buy tickets for themselves and CANNOT receive gifted tickets — but they CAN still gift tickets to other (non-excluded) members. When a raffle bars any groups, the open widget lists them at the bottom ("The following groups are UNABLE to purchase or receive tickets:"). An excluded member trying to buy for themselves sees a notice naming their group; a member trying to gift to an excluded person is told the recipient's group is excluded. (Blocking a gift to an excluded member reads the recipient's groups from the Currency System's member directory, which needs Currency System v1.1.71 or newer and works for any member CS has seen load a page; self-exclusion always works.)

Then add prizes below. Start typing in the item field to search your CS catalog and pick an item from the dropdown (its id + name fill in automatically); or enter a currency amount instead; or just a name for an intangible. Each prize row previews the real item card (name + rarity) or currency chip it will award — so you can see it's right before saving. Click "Save as draft" (to keep editing) or "Save & open" (to start it). Once a raffle opens, its ID, price and caps lock and existing prizes can't be edited or removed — but you can still change the End time, add NEW prizes, and edit the title/preview.

Adding prizes

Prizes are numbered by their order in the list (1, 2, 3…). Each prize row is ONE of:

  • A Currency System ITEM — fill in the item's ID and a quantity. It delivers automatically on roll, through the standard grant pop-up.
  • A CURRENCY amount — fill in the currency box. Also delivered automatically.
  • An INTANGIBLE — just a name (and an optional image), no item or currency. Use this for things CS doesn't track: a custom pet, a breeding slot, an art commission. The winner gets a "You won!" pop-up automatically; you hand the prize over yourself.

Each prize row starts with a TYPE picker — Currency, Item, or Other — and only that type's fields appear: Currency shows the amount box, Item shows the catalog search + quantity, and Other (an intangible) shows a prize name, an image control, a quantity, and a border-tier picker. On an OPEN raffle you can no longer change a prize's type or swap its item, but you CAN still fix its details — the amount, quantity, name, image and border — so typos are easy to correct.

Other (intangible) prize image: one box that takes an image URL OR a symbol/emoji. Leave it blank and the card shows the default symbol from "Intangible prize symbol" (🎁 by default; any emoji or symbol works), colored with the muted text color and sized to fill the card like an item picture. Type a symbol straight into the box to override the default just for that prize.

Because an intangible has no rarity of its own, each Other prize row also has a "Border tier" picker: choose one of your Currency System rarity tiers and that tier's color becomes the card's border (in the widget and in the Static copy). Item prizes already show their own rarity border; currency cards use the Currency System Extras "Currency Card Border" setting.

EMBEDDING IT IN A POST

In any post or page, type the token — for example [raffle=grandopening] — and save. The raffle widget replaces the token. You can embed the same raffle in several posts; they all control the same event. If the ID is wrong or the raffle was deleted, the literal text stays put so nothing looks broken.

The widget changes with the raffle's state:

  • Scheduled — shows the prizes and an "Opens in" countdown, no buy buttons yet.
  • Open — the title bar shows the status and a live Time Remaining countdown; prizes show as item/currency cards; "Purchase Tickets" and "Set Preferences" sit below, with the ticket price and how many you hold.
  • Closed — buttons disappear; it waits for the draw.
  • Rolled — shows the list of winners and the prize each won.

HOW MEMBERS ENTER

Buying tickets

A member clicks "Purchase Tickets", enters a quantity, and clicks Purchase — that's the whole flow for buying for yourself; no name to type. If gifting is on there's a checkbox, "I'm buying these tickets for a friend" — ticking it reveals a username box (with a member dropdown) so they can gift instead. The pop-up shows how many more they're allowed, and buying is refused if they can't afford it or would go over a cap. Buying spends from the member's wallet.

Setting preferences

If a raffle has more than one prize, members click "Set Preferences" to sort the prizes into three groups:

  • Ranked — the prizes they want, most-wanted first. On a win they receive the highest-ranked prize that's still available.
  • Unranked — any prize they leave in the middle pool. If all their ranked prizes are taken, they still receive one of these, based on what's left and their roll order.
  • Do Not Want — prizes they never want. These are never assigned to them; if a member wins but only their Do-Not-Want prizes remain, they're dropped from that draw instead of handed one.

Ranking nothing still lets a member compete — they'll take whatever is left (unless they excluded it). They can change any of this while the raffle is open. (A single-prize raffle skips this step.)

Gifting

Gifting is on whenever the raffle's gift cap is 1 or more (blank or 0 turns it off). When it's on, any member can buy tickets for another member: in the purchase pop-up they tick "I'm buying these tickets for a friend", then type part of a name to pick the recipient from a member dropdown. The only limit is the recipient's GIFT cap — a generous member can gift to as many people as they like. Gifts count toward the recipient's gift cap (separate from their own self-purchase cap), not the giver's cap. A member whose group is excluded from the raffle can't be gifted to (the giver is told), though an excluded member can still gift to others. The recipient sees a "you received N tickets from …" note next time they load the forum. Refunds on a cancelled raffle always go back to whoever actually paid.

FREE RAFFLES

Set the ticket price to 0 and the raffle becomes a free, one-entry-per-person draw: every entrant gets exactly one ticket, gifting is turned off, nothing is charged, and the button reads "Enter Raffle". Because everyone holds one ticket, everyone has equal odds — no separate mode to set up.

ROLLING THE WINNERS

ProBoards has no server, so a raffle can't roll itself the instant its timer ends. Rolling is page-load driven, two ways you can use together:

(A) Manual — after a raffle closes, press "Roll" on it in the admin panel.
(B) Auto — on the Raffle System settings tab, add member GROUPS to "Auto-roll groups". After a raffle closes, the first page-load by anyone in those groups rolls it automatically. Leave it empty for manual-only. Use groups with the "Edit Profiles" power so item/currency prizes deliver; otherwise those wait for the next staff visit (intangible prizes always deliver).

Rolling is safe to trigger more than once — the winners are decided by a fixed formula, so the result is the same no matter who rolls or how many times, and nobody is ever awarded twice.

How winners are chosen

The draw is purely ticket-weighted: every ticket is one slip in the hat, so more tickets means more chances (never a guaranteed win). Each win uses up one ticket, and "Wins per member" is a hard ceiling no matter how many tickets someone holds. Winners get the highest-ranked prize they still want; members who didn't rank get whatever's left over. A prize nobody could receive is reported back to you to hand out or re-roll.

ANNOUNCING & DELIVERING

As soon as a raffle is rolled:

  • The widget in every post shows the winners and their prizes.
  • Each winner is notified on their next visit — item/currency winners get the standard grant pop-up (with your grant message), intangible winners get a "You won!" pop-up with the prize image.

For a public shout-out, open the rolled raffle in the admin panel and click "Announcement". It builds a ready-to-paste block; paste it into the raffle post (or a reply) and SAVE. Saving is what actually notifies the members and turns [item=…] into item cards — a plugin can't send those notifications from a widget it drew on the page. Any winner whose name couldn't be looked up is listed for you to tag by hand (their win pop-up still reaches them).

ENDING A RAFFLE

You can manage a raffle two ways: from the admin panel, or straight from the post via a small ⚙ gear that appears on the raffle widget to staff (see "Who can manage raffles" below). Both offer the same actions for the raffle's state:

  • Edit / Roll / Announcement — as described above.
  • Clear — after a raffle is rolled, "Clear" tidies it away: members' ticket entries for it are dropped, but the raffle's record stays so the winners keep showing in old posts.
  • Cancel — ends a raffle early AND refunds every buyer exactly what they paid (gifters are refunded, not the people they gifted). Use this if a raffle needs to be called off. There are no refunds on the normal close-and-roll path — only on Cancel.
  • Static copy — for a finished (rolled) raffle, this gives you a ready-to-paste block that reproduces the raffle as permanent post content AND doubles as the winner announcement: a big centered title, the preview image, the end date, the prize cards (real items via [item=], currency via [currency=], and intangible prizes via [card=] — all keep their cards), and the winners as [quote] blocks with their prizes inside, so saving the post pings each winner just like the Announcement. Edit the raffle's post, replace the [raffle=id] tag with the whole block, and SAVE. The result renders on its own with no live raffle behind it, so you can then Delete the raffle. (The currency and intangible cards are drawn by CS Extras — you need CS Extras v1.0.76 or newer, with "Item Cards in Posts" enabled.) The prize cards are laid out in a table with fixed-width cells, and CS Extras makes each card fill its cell, so they all come out the same size automatically.
  • Delete — permanently removes the raffle and its results, freeing the storage every raffle otherwise keeps forever. You can only Delete a raffle after it's been rolled or cancelled. Any post still showing that raffle reverts to plain text — so paste its Static copy into the post FIRST if you want to keep the display, then Delete. This is how you keep the plugin's storage from filling up over many raffles.

Who can manage raffles: the "Raffle manager groups" setting (Raffle System tab) picks which member groups get the admin panel and the gear. Forum Admins always can; leave it empty to allow all staff. Whichever groups you choose, also give them WRITE access to the raffle_events key on the Key Permissions tab (and the "Edit Profiles" power to roll tangible prizes), or their actions will appear to work but won't save.

GOOD TO KNOW

  • Everything runs in the member's browser (all ProBoards plugins do), so ticket counts and windows are enforced on trust, not by a server. This is fine for a friendly forum economy; it's not a bank vault.
  • How members see a raffle: ProBoards only hands a plain shared plugin key to a viewer who has personally WRITTEN to it, so the staff-only raffle list (raffle_events) never reaches a member who's just looking. The plugin gets around this by stamping a display-only COPY of the raffle — title, prizes, price, dates, winners — onto the POST itself (the raffle_display key), which loads with the post for everyone who can see it, exactly like a post's view count. Each post carries ONLY the raffle(s) embedded in that post (not your whole raffle history), so the copies stay small and you can run any number of raffles over time without them overflowing. Staff publish that copy automatically whenever they view the raffle post, so a member viewing it afterward receives it. That's why raffle_display must stay Members & Staff (Read + Write), and why the copy carries no delivery secrets — the real prices and results stay staff-only in raffle_events.
  • That copy is display-only and can't be exploited: the REAL prices, caps and results live in the staff-only key, and when you roll, every entry is re-checked against them — any ticket that didn't actually pay the real price, or that slipped past a cap, is simply not counted. Nobody can forge a win or a free ticket by editing what their browser shows.
  • Because of that re-check, don't lower a raffle's price or caps after it opens (the editor locks them for you) — otherwise honestly-bought tickets could be miscounted at roll.
  • Because there's no server, a couple of members entering at the exact same instant can, rarely, nudge slightly past a cap — harmless (a touch more odds), and the currency ledger itself stays correct.
  • A raffle ID can't be reused; pick a new one each event so old tickets never bleed into a new draw.
  • Only staff with the "Edit Profiles" power can deliver item/currency prizes; set your auto-roll group accordingly.

MOBILE (RESPONSIVE) — RECOMMENDED

By default a ProBoards forum renders at desktop width on phones, so it looks tiny and zoomed-out. This plugin can fix that, but it needs TWO steps — one alone won't work:

Step 1 — turn the setting on

Turn ON "Mobile responsive layout" (STRONGLY recommended). (The Raffle System's widgets use the Currency System's pop-ups, so they follow this too.)

Step 2 — add the viewport line to your theme (the part people miss)

Add this ONE line inside the <head> of your theme's Wrapper — ACP > Themes > Layout Templates > Wrapper, e.g. right after the <meta charset> line:

<meta name="viewport" content="width=device-width, initial-scale=1">

Without this line, phones render the forum at desktop width and the responsive layout can't take effect, so the setting appears to do nothing. If your theme already has a viewport tag, you're set — don't add a second one.

Also: turn off ProBoards' separate mobile view

In ACP > Themes, make sure ProBoards' separate "mobile view" is OFF, so phones use your real theme (with your plugins). If it's on, phones get ProBoards' built-in mobile skin, which ignores your theme and plugins entirely.
